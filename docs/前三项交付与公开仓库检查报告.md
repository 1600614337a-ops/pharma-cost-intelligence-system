## 2. 公开仓库构成

公开发布目录由 `scripts/prepare_public_release.py` 自动生成，包含：

- `app/`、`scripts/`、`tests/`完整自研代码；
- `Dockerfile`、`compose.yaml`、跨环境启动/停止脚本；
- `requirements.txt`、可选LlamaIndex依赖、第三方许可证说明；
- 公开版README和6份必要技术/评测文档；
- 文件SHA-256清单 `PUBLIC_RELEASE_MANIFEST.json`。

不包含受限CSV、企业知识文档、报告模板、派生知识索引、生成报告、审核数据库、日志、RPA回执、API Key或本机路径。公开仓库克隆后必须叠加组委会或正式受控提交包提供的数据目录才能运行完整业务场景。

## 3. 跨环境启动

主路径为Docker Compose：Windows、macOS和Linux共用同一镜像，镜像内安装Python 3.12、LibreOffice Writer、Poppler和Noto CJK字体。容器启动前执行与Windows本机相同的数据、索引、模板、107字段契约和LibreOffice预检；Web只映射到主机 `127.0.0.1:8080`，模拟RPA不单独暴露主机端口。

当前Windows验收机未安装Docker Engine，因此本轮完成了Docker文件静态检查、公开镜像构建上下文隔离检查，以及“代码根目录与数据根目录分离”预检；实际镜像构建应在首次具备Docker的目标机上补做并记录。Windows原生一键启动和完整业务链路已有真实端到端PASS证据，不受该环境限制影响。

## 4. 发布前门禁

1. 重新运行 `python scripts/prepare_public_release.py`；
2. 运行 `python scripts/audit_public_release.py release/github-public`，结果必须为PASS；
3. 在发布目录内确认 `git status` 只包含清单中的公开文件；
4. 在具备Docker的目标机执行 `docker compose up --build -d` 并核对 `/health`；
5. 用户确认仓库名称和GitHub账号后再创建公开远程仓库并推送；
6. 公共仓库不得追加受限数据或真实密钥，完整数据通过官方受控渠道交付。
